# Synthetic Forensic Demo Exhibits

**Every file here is fictional and machine-generated.** No real Aadhaar, PAN,
certificate, invoice, medical record or vehicle registration is reproduced,
and none of these documents is valid for any real-world purpose.

## Provenance disclosure

- Generated by `generate_samples.py` (Pillow). `python/.venv/bin/python documents/generate_samples.py`
- All names, addresses, IDs and figures are invented placeholders.
- The Aadhaar number `9999 9999 4321` is a deliberately invalid placeholder.
- The PAN `SAMP9999X` is a placeholder string, not a valid PAN structure.
- QR-like blocks are decorative artwork and are **not** scannable codes.
- Each page carries a "SYNTHETIC SAMPLE / NOT A REAL DOCUMENT" banner and a
  footer reading `fictitious data — synthetic fixture`.
- Figures are chosen so OCR reads them reliably. That is a *fixture* property,
  not a claim about real-world detector accuracy.

## How to demo

1. Start the stack (Node 22 required for the Next.js frontend):
   ```
   export PATH="/opt/homebrew/opt/node@22/bin:$PATH"
   npm run dev                      # http://localhost:3000
   cd python && .venv/bin/python -m uvicorn app.main:app --port 8000
   ```
2. Upload a `*_clean.jpg` then the matching `*_tampered.jpg`.
3. Compare the Semantic Consistency layer and the localised region. The
   tampered invoice should report an arithmetic breach in the grand total.

## Honest limitations

- These fixtures are synthetic artwork, not scans of real documents, so
  pixel-level signals (ELA, noise, smoothing) fire broadly and are not
  discriminating between the clean and tampered variants.
- The discriminating signal here is the **semantic arithmetic layer**, which
  verifies the document's own internal identities.
- A "clean" result means the document is internally consistent. It is not proof
  of authenticity and must not be presented as such.
